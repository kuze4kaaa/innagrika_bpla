# Система взаимодействия двух БПЛА АТ11-2

Проект моделирует последовательную работу двух БПЛА на учебном полигоне 6 на 4 м.

1. Разведчик получает наблюдения и переводит их в систему координат поля F.
2. Компьютер объединяет повторные наблюдения, формирует карту и оставляет в задании только подтверждённые цели класса A.
3. Валидатор проверяет формат, метры, систему F, версии калибровки, срок действия, контрольную сумму, границы, уникальность идентификаторов и запретные зоны.
4. Планировщик строит таблицу расстояний по безопасным переходам между базой и целями. Алгоритм Хелда-Карпа выбирает кратчайший маршрут по этой таблице с посещением всех достижимых целей и возвратом. Python-версия также сравнивает его с методом ближайшей цели и учитывает резерв времени.
5. Исполнитель включает только световой индикатор. Перед включением требуется 1 с устойчивого положения, затем 2 с непрерывного разрешённого действия.
6. Любая потеря допуска выключает светодиод. Потеря подтверждения после включения даёт состояние `UNCERTAIN` и блокирует повтор по тому же `action_id`.

Реальные препараты, опрыскивание и диагностика болезней в проекте не используются.

## Быстрый запуск

Нужен Python 3.10 или новее. Внешние библиотеки для безопасного ядра не требуются.

Проверка всех тестов:

```bash
python3 -m unittest discover -v
```

Проверка карты и расчёт маршрута:

```bash
python3 run_mission_demo.py
```

Запуск 3D-демонстрации:

```bash
python3 run_3d_simulation.py
```

Если браузер открывать автоматически не нужно:

```bash
python3 run_3d_simulation.py --no-browser --port 8080
```

После запуска адрес симуляции: `http://127.0.0.1:8080/index.html`.

Поле 3D-демонстрации занимает 18 × 16 м. Четыре запретные зоны действуют для обоих дронов, а точки появляются после сканирования разведчиком. Кнопка 16× ускоряет ход симуляции.

В симуляторе разведчик летит параллельными галсами с перекрытием полос съёмки. Маршрут огибает известные препятствия и возвращается на прерванный галс сразу за препятствием. Если после основных проходов остались доступные для съёмки клетки, разведчик доснимает их и возвращается на базу. Перед запуском исполнителя симулятор проверяет фактическое покрытие сетки вне препятствий.

Проверки маршрута разведчика можно запустить командой `node --test tests/test_recon_survey.cjs`.

В 3D-симуляторе расстояния для исполнителя считаются по графу видимости с обходом расширенных запретных зон. В маршрут подставляются те же переходы, длины которых использовались при оптимизации. Если замкнутый маршрут по всем разрешённым целям отсутствует, симулятор не запускает исполнителя.

## Структура

- `mission_system/coordinates.py` - гомография изображения и отдельные преобразования локальных систем двух БПЛА в F.
- `mission_system/observations.py` - объединение повторных наблюдений и перевод противоречий в U.
- `mission_system/validator.py` - строгая проверка карты-задания.
- `mission_system/planner.py` - безопасный маршрут, сравнение способов упорядочивания и выбор подмножества при нехватке времени.
- `mission_system/executor.py` - автомат световой операции, журнал и защита от повторов.
- `analytics/` - проверенные расчёты экономики и бюджета погрешностей.
- `simulation_3d/` - наглядная браузерная демонстрация.
- `tests/` - автоматические проверки.
- `docs/TEST_PROTOCOL.md` - протокол сценариев С1-С8.

Папка `scratch/` содержит старые разовые эксперименты и снимки разработки. Она не является набором приёмочных тестов. Актуальные проверки находятся только в `tests/` и `docs/TEST_PROTOCOL.md`.

## Важное ограничение

В репозитории нет набора исходных кадров и размеченной выборки. Поэтому здесь реализованы геометрическая привязка, объединение уже полученных наблюдений, карта, валидатор, планировщик и исполнитель, но нельзя честно заявить измеренную точность распознавания A, B и U.

Для завершения проверки на реальном стенде нужны:

- исходные кадры и независимые контрольные точки;
- реальные калибровки камеры и двух UWB-меток;
- измерения средней и максимальной ошибки UWB;
- журнал реального включения светодиода;
- независимая видеозапись или данные контрольного трекинга.

Числа 0,06 м, 0,23 м, 0,3 с и 15 минут являются требованиями учебного кейса. Их нельзя выдавать за подтверждённые характеристики оборудования без испытаний.
